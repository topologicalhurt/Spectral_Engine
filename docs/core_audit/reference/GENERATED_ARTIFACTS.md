# Generated artifacts — the registry (canon, no plan)

Every file the build *generates* and *commits in-source* is listed here. Each has a named
generator, an `AUTO-GENERATED by tools/spectral_tools/generators/<x>.py` banner, a
build-tree-stamp generate target, and a **verify-on-build** drift guard wired onto the
targets that consume it. The registry-completeness gate
(`tests/tools/test_generated_artifacts.py`) fails if a committed banner-bearing file is
missing here (i.e. ships without a verify guard) — the hole that let `spectral_lut_data.h`
drift unguarded for a long time.

## Committed generated build inputs

| Committed file | Generator | Generate / verify targets | Gated on |
|---|---|---|---|
| `core/spectral_hash_resources_xx32_xx3.c` | `resource_hashes.py` | `generate_resource_hashes` / `verify_resource_hashes` | desktop, simulate(+daisy), embedded_arm{,_float,_restricted} |
| `core/spectral_lut_data.h` | `lut_generator.py` | `generate_lut` / `verify_lut` | desktop, simulate(+daisy), embedded_arm{,_float,_restricted} |
| `drivers/metal/spectral_osc_metal_generated.h` | `metal_osc.py` | `generate_metal_osc` / `verify_metal_osc` | desktop (Metal driver TU) |

## The pattern (how to add one)

1. The generator supports `--mode generate|verify`; verify regenerates in-memory and
   **byte-compares** to the committed file (regenerate-and-diff), exiting non-zero on drift.
2. The `add_custom_command` `OUTPUT` is a **build-tree stamp**, never the committed file —
   CMake adds every OUTPUT to `clean`, so a committed file as OUTPUT lets `--target clean`
   delete a git-tracked source (the footgun fixed in commit `0f647138`). The generator
   rewrites the committed file in place as a clean-invisible side effect.
3. A `verify_<x>` target runs `--mode verify` and is `add_dependencies`'d onto every target
   that compiles the artifact, so drift FATALs the build.
4. Add a row above + a `REGISTRY` entry in `test_generated_artifacts.py`.

## Generated **build inputs** vs generated **measurement intermediates**

Only generated *build inputs* are committed + verified. Generated *measurement
intermediates* (the M7-census `.s` files — `build/perf_model/arm32_m7.s`,
`kernel_wrappers.s`, `loop_*.s` — produced ephemerally to count instructions) are **not**
committed; they are regenerated per measurement run and live under the git-ignored
`build/`. The committed perf artifact is the frozen *counts* (`tests/fixtures/m7_baseline.json`),
not the asm text.

## Reserved: generated assembly

There is **no** committed generated assembly today. If a kernel ever ships codegen'd or
hand-tuned `.s` as a build input (not a measurement intermediate), it lives under a
dedicated committed `asm/` folder and obeys this same pattern (banner + stamp +
verify-on-build + a registry row). Do not pre-create the folder speculatively — wire it
the day real generated asm ships.
