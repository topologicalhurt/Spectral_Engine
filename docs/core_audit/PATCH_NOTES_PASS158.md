# Patch notes — Pass 158: retire the interim ARM oracle (Phase A / A1b#4 closure)

## Problem

`tests/arm_oracle/` held the interim behavior oracle from early Phase A:
`oracle.py` (capture/check SHA-256 of the `simulate` build's output over a
fixture × argument matrix), `goldens.json` (the captured hashes), and the input
fixtures (`sine_bin.wav`, `sine_offbin.wav`, `two_tone.wav`, `silence.wav`).

Two reasons it is now dead weight:

1. **Its goldens are stale by design.** Pass 157 moved all sim audio onto the
   real `spectral_arm32_process`. The captured hashes were taken against the old
   parallel reimplementation, so every `check` would now diff — they no longer
   describe the code that runs.
2. **It was always interim, and its successor has landed.** `oracle.py`'s own
   docstring says: *"Superseded by the tolerance-based compiled parity harness in
   Phase D."* That harness — `tests/arm_core/test_arm32_process.c`, registered as
   the CTest `arm32_process_correctness` — exists and is green. It drives the real
   `spectral_arm32_init/load/process` directly and is the authoritative correctness
   gate. The ULTRAPLAN A1b rework list (item 4) called for exactly this retirement
   "once the CTest harness lands."
